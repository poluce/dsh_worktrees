# 打包安装与分发

## 最小可安装包

```
hello-plugin/
├── package.json       # 声明 dsh.bundle
├── cordis.patch.yml   # 配置层：插入插件行
└── index.js           # 插件模块
```

**package.json（bundle manifest）**：

```json
{
  "name": "dsh-hello-plugin",
  "version": "0.1.0",
  "type": "module",
  "main": "index.js",
  "files": ["index.js", "cordis.patch.yml"],
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
}
```

- `dsh.bundle.patch` 让 `dsh plugin add` 认出这是 bundle 并加入 profile 的 bundles 层。
- 没有 `dsh.bundle` 声明的包也能作为普通依赖安装，但不贡献组合层（`dsh plugin` 会打印警告）。
- `files` 必须包含入口和 `cordis.patch.yml`；`dsh.bundle.patch` 必须是相对包根的路径。

**cordis.patch.yml**：

```yaml
- insert:
    - id: hello
      name: dsh-hello-plugin
```

- 顶层 YAML 数组；`insert` 追加组合行。
- `id` 是配置树中稳定的行身份（全局唯一）；`name` 是 Node 可解析的包名或导出路径。
- 行 `id` 必须与插件导出的 `name` 一致，否则工具静默不注册。
- 后层按 `id` 覆盖前层；目标行的 `config` 是整段替换，不是深合并。

## 安装到 profile

```sh
dsh plugin --profile demo add ./hello-plugin
dsh --profile demo --dump-config   # 不启动，验证组合树里出现插件层
dsh --profile demo                 # 启动
dsh plugin --profile demo remove dsh-hello-plugin   # 同时移除依赖和层
```

- `dsh plugin` 是 profile 目录里的 pnpm 转发层，支持 npm 包、本地路径、tarball、Git 地址。
- 首次使用会初始化 profile（`@deepseek-ai/dsh-base` 作为第一个 bundle）。
- 安装后需要重启该 profile（manifest/bundles 层和 client package metadata 在进程内缓存）。
- 验证用 `--dump-config`（只打印组合，不 boot）；`--dump-default-config` 只打印 bundle 层、跳过用户层与 `--patch`，可作坏 `cordis.patch.yml` 时的恢复诊断。

## 配置层生效顺序

1. profile 的 `dsh.profile.bundles` 列表中的各 bundle patch，按列表顺序；
2. profile 自己的 `cordis.patch.yml`；
3. `$DSH_HOME/cordis.patch.yml`；
4. 命令行 `--patch` 覆盖层，按参数顺序。

后层按行 `id` 覆盖前层，整段替换 `config`。你的 patch 可以按 `id` 覆盖更早层的行，但必须重述该行需要的每个键。用户可以在自己的 `cordis.patch.yml` 里覆盖你的行而不动你的包。

## 分发方式

| 方式 | 消费者行为 | 作者责任 |
|---|---|---|
| npm 包 | 安装预构建产物 | 发布前构建，`files` 包含运行时文件 |
| tarball（`pnpm pack`） | 安装本地不可变文件 | 检查包内容与校验和 |
| Git 依赖 | 获取源码，可能运行 `prepare` | 构建自包含，文档写明精确 commit |

## GitHub 安装的构建脚本坑

Git 安装获取的是**源码不是构建产物**，TypeScript 包没有 `lib/` 会加载失败。两边都要做：

- **作者**：提供自包含的 `prepare` 脚本（pnpm 在 Git 安装后运行它），从源码构建发布入口，不依赖 monorepo 兄弟目录等 dev-only 上下文。
- **用户**：pnpm ≥10 默认拒绝运行 Git 依赖的 `prepare`，第一次 `add` 会失败；把 pnpm 打印的包 key 写进 profile 的 `pnpm-workspace.yaml`：

  ```yaml
  allowBuilds:
    dsh-hello-plugin: true
  ```

  然后重跑 `add`。

这个允许等于**授权在安装时于你的机器上执行该包代码**（在 agent 沙箱之外）。只允许你信任的源码，并固定 commit（`github:you/hello-plugin#<sha>`）。

不想让用户做这个决定就分发构建产物：npm 发布（`lib/` 在 `pnpm publish` 时构建好）或 tarball。

## 发布到 npm

```sh
npm login
npm publish --access public
```

发布后用户 `dsh plugin --profile web add dsh-my-plugin` 即装即用。仓库打 `dsh-plugin` topic 便于被发现：

```sh
gh repo create 你的名字/你的仓库 --public --source . --push
gh repo edit --add-topic dsh-plugin
```

## 版本与 registry 注意（内测期）

- `@deepseek-ai` scope 需要官方只读 token（`.npmrc` scope 鉴权）；token 只放环境变量或临时 userconfig，绝不写进项目 `.npmrc` / 提交 / 日志。
- peer 范围必须写 rc 通道（如 `^0.0.1-rc.1`），普通 `^0.0.1` 不匹配 `0.0.1-rc.x`。
- **CLI 与 bundle 版本必须同通道**：npx 默认 CLI 可能是 `next`（rc.2），而 `dsh plugin add` 默认装 `latest`（rc.1），混装会出现 "Failed to load plugins … waiting for service" 类错误。固定 `npx -p @deepseek-ai/dsh@0.0.1-rc.1` 或全部升级 `next`。
- 网络慢时公共包可走国内镜像（registry.npmmirror.com），`@deepseek-ai` scope 仍需官方 registry + token。
