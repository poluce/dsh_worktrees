# 验证与发布

## 验证金字塔（从快到慢）

1. `pnpm typecheck`（双 program，host + client）
2. `pnpm build`（tsc host → tsc client → tsdown）
3. 纯逻辑验证：状态机、依赖深度、fold、布局提取成无 ctx 依赖的纯函数，脚本直接 import `lib/*.js` 断言；文件持久化在临时目录跑真实往返
4. `dsh --profile <scratch> --dump-config`：验证组合树里出现插件行（离线，不 boot）
5. headless 真实任务：`dsh --profile headless "一个小而可判定的任务"`（需要 API key）
6. 独立 web 实例 + curl 探名册/路由
7. 真实浏览器 GUI 端到端（跑任务、DOM 探针断言面板/卡片）

验证全程使用**独立 profile/独立端口**，不触碰正在运行的实例。

## 基线检查

```sh
pnpm typecheck
pnpm build
pnpm test             # package.json 声明时运行
pnpm verify           # package.json 声明时运行
git diff --check
```

先读 `package.json.scripts`，不要假设所有仓库都有同名聚合脚本。项目级 verify/check 至少覆盖：

- 纯业务规则和状态迁移；
- 临时目录中的文件往返、锁、归档/恢复；
- client 可独立测试的投影/折叠纯函数。

## Host 与真实组合验证

- 单元测试覆盖 schema、service、失败和 disposer。
- 不只手搓 `ctx.plugin()`：至少一个测试通过真实 Loader/patch 组合启动，断言用户可见表面。
- 先用 `dsh plugin --profile <scratch> add <pkg>` 创建非内置 scratch profile，再 `dsh --profile <scratch> --dump-config`，确认 bundle 层、行 id、name、config 和注入顺序。
- 真实任务用 `dsh --profile headless "..."`，不要发明 `dsh run` 子命令（web profile 无 headless-runner 行，报 "profile web takes no task" 时改用 headless profile）。

## Client 验证

- client 测试用 jsdom lane；通过 SlotTestRuntime 或最小 fake services mount 插件。
- 断言 slot 注册、渲染、session 隔离、connection reset、dispose 后 registry/DOM/style/controller 均清理。
- 每个 registry 贡献至少有一个 HMR/dispose 安全测试。
- GUI 用独立 web profile 和真实浏览器，验证名册、路由、交互、刷新、宽窄屏、滚动、焦点和 reduced motion。

## 从零安装验证（发布前）

1. 使用全新临时 `DSH_HOME`/profile。
2. 按 README 的精确命令安装。
3. 断言 profile dependency 与 `dsh.profile.bundles`。
4. 断言所有 exports、host/client bundle、patch 和静态资源存在。
5. `--dump-config` 必须出现插件层。
6. 启动后检查 host route、client roster 和真实 UI。

仓库仍私有时，可把待发布内容复制到临时 Git repo 并提交，再通过 `git+file://...` 安装；这能验证"Git 获取的内容"而不是当前 checkout 的未提交文件。若包声明了 `prepare`，还需在 profile 的 `pnpm-workspace.yaml` 加 `allowBuilds`。

## 发布 checklist

- [ ] 官方仓库和核对的 commit 已记录。
- [ ] 本地模块通过一个显式 overlay 加载。
- [ ] 每个硬服务依赖都出现在 `inject`。
- [ ] 工具参数和 canonical 输出都经过校验。
- [ ] 外部资源有生命周期 disposer。
- [ ] 包包含构建后的入口和 patch 文件。
- [ ] `dsh.bundle.patch` 在安装后的包内可解析。
- [ ] `--dump-config` 显示预期的 bundle 和行。
- [ ] 干净 profile 启动并调用工具。
- [ ] 移除同时删除依赖和组合层。
- [ ] Git 安装固定 commit，构建权限显式。
- [ ] 产物无 `.ts` 残留：`grep -rE "from './[^']+\.ts'" lib/ || echo "产物无 .ts 残留"`
- [ ] `npm pack` 后检查 tarball 的 exports 指向存在。

## 完成标准

- 运行面最小，manifest、exports、patch 与产物一致。
- 必需 inject 和可选 service 边界清楚；pending/failed 状态可诊断。
- route、registry、timer、watcher、DOM、React root 和存储均可清理。
- Conversation Node 可确定性重放，owner 与去重维度正确。
- client import 未越过模块表，host/client 类型隔离。
- 持久化有并发与崩溃语义，不依赖偶然 cwd。
- typecheck、build、verify、真实组合、从零安装和需要的 GUI 验证通过。
- README 安装命令与实际分发形态一致。
- 未执行未经授权的 commit、push、发布或 visibility 变更。
