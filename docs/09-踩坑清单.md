# 踩坑清单

按开发顺序排列，全部来自社区实战记录。

## 工具与 schema

| 症状 | 根因 | 解决 |
|---|---|---|
| `Property 'tools' does not exist on type 'Context'` | 双 Cordis：裸 `cordis` 与 `@deepseek-ai/cordis` 是两个模块，dsh-tools 类型只增强 scoped | 全链统一 `@deepseek-ai/cordis`（import/peer 都是） |
| 插件崩溃报 "no service available" | 忘记 `export const inject = ['tools']` | 补上；`ctx.tools` 运行时是 `undefined` |
| 工具注册了但模型从不调用 | `description` 没写清何时用 | 重写 description，它就是模型契约 |
| patch 行 `id` 与 `export const name` 不一致 | 工具静默不注册 | 保持一致 |
| object 输出 schema 注册失败 | 缺 `additionalProperties` | 显式写 `additionalProperties: false`（或按需 `true`） |
| `required: ['city']` 数组 / `required: false` 破坏类型推断 | DSL 只支持属性内联 `required: true` | 改写 |
| 用 `run(...)` 而不是 `execute` | API 是 `execute` | 改写 |

## TypeScript 与构建

| 症状 | 根因 | 解决 |
|---|---|---|
| `TS5097: import path can only end with '.ts'` | tsconfig 缺 `allowImportingTsExtensions` | 补 + `rewriteRelativeImportExtensions`（产物自动 `.js`） |
| 产物 `lib/index.js` 里还是 `./x.ts` | 同上缺 rewrite | 重新构建，验证产物 |
| `TS5096` + `TS5023`（typecheck 过、emit 挂） | TypeScript < 5.7 | `typescript@^5.9`，装完 `tsc --version` 确认 |
| `TS2591: Cannot find name 'Buffer'` | 缺 node types | `types: ["node"]` + devDependencies `@types/node` |
| JSX 报成串 `TS1005 '>' expected` | 入口文件是 `.ts`，TS 只在 `.tsx` 里解析 JSX | 含 JSX 的文件一律 `.tsx`，输出名不变 |
| `declare module` 合并不生效（TS2664 / 事件不在 union 里） | 模块增强只对已加载进 program 的模块生效；纯 `declare module` 文件零 import 时目标模块从未被加载 | 合并文件顶部加 `import type {} from '<目标模块>'`（编译期擦除，不进 bundle） |
| 嵌套闭包内判别联合窄化失效 | 函数参数的窄化在嵌套箭头函数内不保留 | 守卫后先 `const field = match.event.data.field` 提取局部变量 |
| `ctx.sessions.open` 报 "Property 'open' does not exist" | host/client 同名 Context 成员冲突，同一 program 内取先声明者 | 拆双 tsc program（见第 8 章） |
| tsdown CSS 报 ENOENT（module.css 找不到） | 漏了 `sourceAssetPath` 的 lib→src 回退 | resolveId 找不到 emitted 路径时把 `/lib/` 段替换为 `/src/` 再查 |
| `tsc` 报错却生成了坏产物 | `noEmitOnError` 默认 false，报错仍 emit | 构建失败即停（`\|\| exit 1`）+ 产物统一验 `.ts` 残留 |

## 运行时与挂载

| 症状 | 根因 | 解决 |
|---|---|---|
| 首次启动随机报 `no subagent provider "spawn" is registered` | provider 注册是兄弟插件 effect，Loader 并发激活下可能晚于你的 `apply`；`inject` 只等服务不等 provider | 不在 apply 校验 provider；在首次真正使用时 `getProvider` 校验（最早可解析点 fail-loud） |
| 浏览器名册不收录插件 | `dsh.client` 声明畸形、`exports["./client"]` 缺失或 bundle 不存在 | 修正 manifest/export 后**重启 host**（包元数据和负结论按名称缓存） |
| 页面报 "Failed to load plugins … waiting for service: settingsScope" | CLI 与 bundle 版本不同通道（npx 默认 next/rc.2，`dsh plugin add` 默认 latest/rc.1） | 固定 `npx -p @deepseek-ai/dsh@0.0.1-rc.1` 或全部升级 `next` |
| `--patch` 绝对路径插件的裸导入找不到 | 插件目录向上找 node_modules 找不到 | 开发期给插件目录软链依赖：`ln -s ~/.dsh/profiles/node_modules/@deepseek-ai node_modules/@deepseek-ai` |
| headless bundle 装不进新建 profile | `@deepseek-ai/dsh-headless` 依赖的 `@deepseek-ai/dsh-code-runtime-worker` 不在 npm 上 | e2e 用默认 headless profile + `--patch`，别新造 profile |
| `dsh plugin` 报 "pnpm not found on PATH" | 没装 pnpm | `npm i -g pnpm`（国内镜像 `--registry=https://registry.npmmirror.com`） |
| Windows 报 `ERR_UNSUPPORTED_ESM_URL_SCHEME`（protocol 'f:'） | 绝对 Windows 路径被 Node ESM 当 URL 协议 | 用 `pathToFileURL()` 生成规范 file:// URL 写进 patch |
| 插件安装成功但没有层出现 | 包没有 `dsh.bundle` 声明 | 加 `dsh.bundle.patch`；无声明只作普通依赖 |

## 客户端 UI

| 症状 | 根因 | 解决 |
|---|---|---|
| 轮询乱序闪烁 | 1s setInterval + fetch 重叠 | in-flight 标志或序号，只应用最新 |
| 200 但形状异常时闪烁 | `body.teams ?? []` 不够 | `Array.isArray(body.teams)` 校验形状 |
| 闭包内 setState 与事件监听不同步 | window 监听器读旧 current | 用 ref，在 effect 中同步；不要 render-phase 写 ref |
| 导航后面板不收起 | 依赖自动收起宽限 | 点击跳转子会话时同步 `setOpen(false)` |
| 历史数据身份冲突 | 可重复业务 id 单独作 key | `${ownerSessionId}:${businessId}` 复合身份，restore/dedup 同样匹配 owner |
| 异步卸载后 setState | 轮询/归档 fetch/timeout 未防护 | 全部 cancelled/disposer |

## 会话事件

| 症状 | 根因 | 解决 |
|---|---|---|
| 会话文件"只有 header" | 误用单帧解码 API（`decompressZstdFrame`）；dsh 会话是多帧 zstd 追加写入 | 用 `scanZstdFrames` + decoder 逐帧解 |
| `session.append` 抛错拖垮工具 | 事件写入失败未处理 | 包一层 try/warn 降级 |
