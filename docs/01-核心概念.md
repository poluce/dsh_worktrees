# 核心概念

## DSH 与插件

DeepSeek Harness（dsh）是 DeepSeek 开源的 Agent 框架，"一切皆插件"：模型、工具、会话、技能、UI 都是 Cordis 插件。插件容器是 Cordis 服务框架的 fork（`@deepseek-ai/cordis`）。

一个插件就是一个 TypeScript/JavaScript 模块，导出 `apply` 函数。框架加载插件时调用 `apply`，传入 `ctx` 上下文对象，插件通过 `ctx` 注册能力：

```ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'my-plugin'

export function apply(ctx: Context) {
  // 在这里注册能力
}
```

这就是完整配置。插件可以注册：工具（模型可调用）、命令（用户可用）、服务（其他插件可消费）、HTTP 路由、会话事件、浏览器 UI 等。

## 插件三要素

| 导出 | 作用 |
|---|---|
| `name` | 插件唯一标识，必须与 patch 文件里的行 `id` 一致 |
| `inject` | 声明依赖的服务，框架等这些服务就绪后才调用 `apply` |
| `apply(ctx, config)` | 初始化函数，注册所有能力 |

```ts
export const name = 'my-tool-plugin'
export const inject = ['tools']   // 必需服务；未就绪时插件保持 pending

export function apply(ctx: Context) {
  ctx.tools.register(/* ... */)
}
```

`inject` 是生命周期依赖，不是文档注释。不声明就访问 `ctx.tools` 会得到 `undefined` 并崩溃。

## 三种插件形态

函数形式（大多数情况够用）：

```ts
export const name = 'my-plugin'
export const inject = ['tools']
export function apply(ctx: Context) { /* ... */ }
```

对象形式：

```ts
export default {
  name: 'my-plugin',
  inject: ['tools'],
  apply(ctx: Context) { /* ... */ },
}
```

类形式（插件要向其他插件提供服务时用）：

```ts
import { Service, type Context } from '@deepseek-ai/cordis'

export default class MyService extends Service {
  static inject = ['tools']
  constructor(ctx: Context) {
    super(ctx, 'myService')   // 'myService' 是服务名
  }
}
```

## 生命周期与自动清理

通过 `ctx` 注册的一切——事件监听、工具、定时器——在插件卸载时自动清理，不需要手动 removeListener / clearInterval。

需要显式清理的外部资源（网络连接、文件句柄等）用 `ctx.effect()` 提供 disposer：

```ts
export function apply(ctx: Context) {
  ctx.effect(() => {
    const timer = setInterval(() => console.log('heartbeat'), 5000)
    return () => clearInterval(timer)   // 插件卸载时执行
  })
}
```

所有长生命周期资源（路由、监听器、watcher、timer、React root、DOM、socket）都必须归当前 fiber，用 `ctx.on()` 或 `ctx.effect(() => disposer, label)` 管理。配置热更新（HMR）会卸载旧实例再加载新实例，注册项是 effect 所以不会残留。

## 两个核心概念：bundle 与 profile

- **bundle**：作者分发的东西，一个 npm 包。`package.json` 里的 `dsh.bundle.patch` 指向一个配置层文件（`cordis.patch.yml`），回答"这个包贡献了什么"。
- **profile**：用户运行的东西，`$DSH_HOME/profiles/<name>/` 目录，描述一个可运行的组合。`dsh.profile.bundles` 保存有序的 bundle 列表，回答"哪些 bundle 以什么顺序组合"。

bundle 是作者写的，profile 是 `dsh plugin` 命令维护的，不要手写 profile manifest。

## Host 与 Client 两面

一个可安装插件可以同时扮演两个角色：

- **host 面**（Node 进程）：包根的 `lib/index.js`，作为组合树里的一行插件挂载，注册工具、服务、HTTP 路由、会话事件。
- **client 面**（浏览器）：包子路径 `./client`（`lib/client.js`），被 `dsh-client-modules` 扫描进 `window.__DSH_BOOT__` 名册，在浏览器里作为 Cordis 插件跑 `apply(ctx)`，渲染 UI。

形态判断：工具、system prompt、HTTP、持久化、provider 属于 host；slot、Conversation Node、浏览器状态和浮层属于 client；host 能力需要 Web 可视化才做 host + client。没有 Web 需求就不要声明 `dsh.client`，也不要构建 client bundle。

## 本地开发两种加载方式

**方式一：`--patch` 覆盖层（开发期，不需要 pnpm）**

```yaml
# my-plugin.yml
- insert:
    - id: my-plugin
      name: '/绝对路径/到/插件/index.js'
```

```sh
dsh --profile headless --patch ./my-plugin.yml "任务"
# 或 Web
dsh web --patch ./my-plugin.yml
```

注意：patch 里的插件路径必须是绝对路径；插件内裸导入（如 `@deepseek-ai/dsh-tools`）从插件自己的目录向上找 node_modules，找不到会启动失败，开发期给插件目录软链依赖即可。

**方式二：正式安装（需要 pnpm）**

```sh
dsh plugin --profile <profile> add <包名或本地路径>
```

`dsh plugin` 转发给 profile 目录里的 pnpm，并把带 `dsh.bundle` 声明的包 reconcile 进 bundles 层。安装后需要重启该 profile。

## 配置层生效顺序

有效配置按以下顺序叠加（后层按行 `id` 覆盖前层）：

1. profile 的 `dsh.profile.bundles` 列表中的各 bundle patch，按列表顺序；
2. profile 自己的 `cordis.patch.yml`；
3. `$DSH_HOME/cordis.patch.yml`（机器级偏好）；
4. 命令行 `--patch` 覆盖层，按参数顺序。

后层覆盖前层时，**整段替换**该行的 `config` 值，不是深合并单个键。所以覆盖时要重述所需键。
